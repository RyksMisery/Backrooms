# P-13 — stitched render-world для проходимого gateway

## Статус

Следующий основной эксперимент после сброса контекста. Не реализован.
Первый и единственный продуктовый маршрут прототипа:
`hub_to_office ↔ office_to_hub`. Центральный gateway не тестировать и не
менять.

P-12 отключён в продукте: `_portal_light_bridge` не создаётся, а структурный
валидатор запрещает его runtime-root. Лабораторные файлы P-11/P-12 сохранены
как доказательства и не являются активной системой.

## Причина

Текущий live portal выводит внутри апертуры изолированную render-копию только
целевой области. Она не получает полный взаимный свет текущей области. После
commit portal-texture сменяется обычным рендером настоящей цели; отличаются
receiver-свет, тени, геометрия рамки и состояние LF3-пула.

Перенос отдельных ламп, калибровка энергии, fill, feather и receiver-overlay
уже проверялись и не дали универсальной бесшовности.

## Контракт P-13

Для активной связи создаётся отдельный render-only `World3D`:

1. визуальная копия source-side neighbourhood;
2. target `SpaceInstance`, пристыкованный точным
   `target_anchor * half_turn * inverse(source_anchor)`;
3. свет обеих сторон, их актуальное LF3-состояние и необходимые shadow-casters;
4. синхронизированные видимые динамические объекты без физики, звука и gameplay;
5. камера с теми же transform, projection, Environment и кадром обновления,
   что основная камера.

Пока свет одной стороны способен влиять на видимые receivers другой, stitched
viewport является источником всего экранного кадра. Ограничивать его только
апертурой нельзя: свет target должен быть виден на source-полу и стенах перед
проёмом. На commit меняется только логический активный `SpaceInstance`; тот же
render-контекст сохраняется. Обычный рендер возвращается после окклюзии gateway
или доказанного нулевого светового вклада удалённой стороны.

## Минимальный порядок реализации

1. Выделить reusable `stitched_gateway_render_module.gd`; не добавлять логику
   P-13 непосредственно в `level_e.gd` кроме подключения и anchors.
2. Собрать A/B одного неподвижного mapped pose: обычный target и stitched target.
3. Добавить source neighbourhood и проверить, что target-свет реально меняет
   source-пол только в stitched-world.
4. Переключить офисный маршрут на полный stitched frame возле gateway.
5. Сохранить один и тот же viewport на N-2…N+2 commit, затем убрать различие
   source/target рамок и LF3 membership.
6. Только после визуального допуска обобщать на другие `GatewaySpec`.

## Ворота допуска

- визуально нет линии на полу, обеих стенках и четырёх кромках рамки;
- нет wall-flash или изменения экспозиции на commit;
- mapped pose до/после commit визуально тождественны без settle-кадров;
- штатный свет, `ярко → темно` и `темно → ярко`;
- yaw `±20/±35`, lateral `±0.45 м`, проход в обе стороны;
- 90 неподвижных кадров без изменения теней;
- в настоящем игровом мире нет phantom lights, коллизий или gameplay-копий;
- измерена стоимость полного дополнительного кадра и определён момент
  безопасного возврата к обычному рендеру.

Ни один маркер завершения бота сам по себе не означает визуальный допуск.
