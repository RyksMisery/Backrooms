# Backrooms — игра-головоломка-лабиринт (Godot 4.6, Forward+, Jolt)

> Этот файл — точка входа для ИИ-агента (Claude Code / Codex).
> Он намеренно короткий. Вся актуальная документация — в `docs/`.
> `CLAUDE.md` и `AGENTS.md` идентичны: правь оба одинаково или правь только `docs/`.

## Прочитать перед работой (порядок важен)

1. `docs/glossary.md` — единицы, размеры, актуальные имена файлов. **Единый якорь.**
2. `docs/PROJECT_CONTEXT.md` — git-процесс, ветки, структура папок.
3. `docs/plan_areas_v2.md` — **актуальный план разработки** (occupancy-сетка). Трекер задач.
4. `docs/areas.md` — правила областей и стыковки.
5. `docs/lights.md` — правила света.
6. `docs/map.md` — правила миникарты.
7. `docs/gameplay.md` — игровые механики (ноклип, головоломки, провал, концовки).
8. `docs/templates.md` — каталог шаблонов областей + превью-харнесс.

## Актуальная архитектура — одна, не путать

- **Действующий подход: occupancy-сетка.** Сначала единая логическая карта
  занятости (пол/потолок/стены/проёмы/колонны/перегородки/провалы/свет),
  затем builder схлопывает её в меши и коллизии. Файл: `level_areas.gd`.
- **Заморожено как эталон атмосферы/света: `level_blueprint.gd`** — не трогать.
- **Устаревший подход (префабы-коробки, 9 типов): архив** в
  `docs/legacy-prefabs.md`. НЕ использовать для новой генерации, оставлен
  только как справка по геометрии отдельных пространств.

## Соглашения по работе

- Не работать напрямую в `main`. Ветка на задачу (см. `docs/PROJECT_CONTEXT.md`).
- При внесении изменений не расписывать сделанное, если не просили, — просто правка кода.
- Любое изменение правил/размеров/механик — сначала в `docs/`, потом в коде.
  `docs/` — источник правды, код следует за ним.
